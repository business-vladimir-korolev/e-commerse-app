# ТЗ: E-commerce App

Техническое задание на backend интернет-магазина с JWT-авторизацией, корзиной, оплатой через Stripe и запуском в Docker.

## 1. Цель проекта

Создать REST API для интернет-магазина, которое:

- позволяет пользователям регистрироваться, входить, просматривать товары, собирать корзину и оплачивать заказ;
- даёт администратору управлять каталогом, ценами и остатками;
- интегрируется с внешним платёжным сервисом Stripe;
- запускается одной командой через Docker Compose.

Учебная цель: научиться строить приложение с большой бизнес-логикой и сложной моделью данных, работать с внешними сервисами и авторизацией.

## 2. Стек и инфраструктура

| Компонент       | Выбор                                       |
|-----------------|---------------------------------------------|
| Язык            | Go                                          |
| HTTP-роутер     | chi или gin                                 |
| База данных     | PostgreSQL                                  |
| Доступ к БД     | pgx или sqlx                                |
| Миграции        | golang-migrate или goose                    |
| Авторизация     | JWT (golang-jwt), пароли через bcrypt       |
| Оплата          | Stripe (тестовый режим), stripe-go          |
| Контейнеризация | Docker, Docker Compose                      |
| Проверка API    | Postman                                     |

Фронтенд (HTML, CSS, шаблоны) делается после готового API и не обязателен.

## 3. Функциональные требования

### 3.1 Пользователи

- Регистрация по email и паролю.
- Вход с выдачей JWT-токена.
- Роли: `user` и `admin`. Роль хранится в БД и передаётся в токене.

### 3.2 Товары

- Просмотр списка товаров с пагинацией.
- Поиск по названию (параметр `search`).
- Просмотр одного товара.
- Публичный доступ без авторизации.

### 3.3 Корзина

- Просмотр своей корзины.
- Добавление товара с указанием количества.
- Изменение количества.
- Удаление товара из корзины.
- Проверка существования товара и достаточного остатка на складе.

### 3.4 Заказ и оплата

- Оформление заказа из корзины (checkout).
- Цены берутся из БД на момент оформления и фиксируются в заказе.
- Создание платежа в Stripe (PaymentIntent или Checkout Session).
- Обработка webhook от Stripe: при успешной оплате заказ получает статус `paid`, остатки уменьшаются, корзина очищается.
- Статусы заказа: `pending`, `paid`, `failed`, `cancelled`.

### 3.5 Админ-панель (API)

Доступна только роли `admin`:

- добавление, редактирование и удаление товаров;
- установка цен;
- управление остатками;
- просмотр заказов (по желанию).

Первый админ создаётся вручную в БД или seed-скриптом, не через публичную регистрацию.

## 4. Модель данных

| Таблица     | Поля                                                                        |
|-------------|-----------------------------------------------------------------------------|
| users       | id, email (unique), password_hash, role, created_at                         |
| products    | id, name, description, price (в центах, int), stock, created_at, updated_at |
| carts       | id, user_id (unique), updated_at                                            |
| cart_items  | id, cart_id, product_id, quantity                                           |
| orders      | id, user_id, status, total_amount, created_at                               |
| order_items | id, order_id, product_id, quantity, unit_price                              |
| payments    | id, order_id, stripe_payment_id, status, amount, created_at                 |

Правила: цены хранятся целым числом в минимальных единицах валюты; у пары (cart_id, product_id) уникальный индекс; остаток не может быть отрицательным.

## 5. API-эндпоинты

| Метод  | Путь                     | Доступ    | Описание                      |
|--------|--------------------------|-----------|-------------------------------|
| POST   | /api/register            | публичный | Регистрация                   |
| POST   | /api/login               | публичный | Вход, выдача JWT              |
| GET    | /api/products            | публичный | Список, пагинация, поиск      |
| GET    | /api/products/{id}       | публичный | Один товар                    |
| GET    | /api/cart                | user      | Просмотр корзины              |
| POST   | /api/cart/items          | user      | Добавить товар                |
| PATCH  | /api/cart/items/{id}     | user      | Изменить количество           |
| DELETE | /api/cart/items/{id}     | user      | Удалить товар                 |
| POST   | /api/checkout            | user      | Создать заказ и платёж        |
| GET    | /api/orders              | user      | Мои заказы                    |
| POST   | /api/webhooks/stripe     | Stripe    | Результат оплаты              |
| POST   | /api/admin/products      | admin     | Создать товар                 |
| PUT    | /api/admin/products/{id} | admin     | Изменить товар, цену, остаток |
| DELETE | /api/admin/products/{id} | admin     | Удалить товар                 |
| GET    | /api/admin/orders        | admin     | Все заказы                    |

Ответы в формате JSON, корректные HTTP-коды (400, 401, 403, 404, 409, 500), единый формат ошибок.

## 6. Безопасность

- Пароли только в виде bcrypt-хеша.
- JWT с ограниченным сроком жизни, секрет из переменных окружения.
- Middleware проверки токена и отдельное middleware проверки роли admin.
- Цена и сумма заказа никогда не принимаются от клиента.
- Webhook Stripe проверяется по подписи.
- Валидация всех входных данных.
- Ключи и пароли не хранятся в репозитории; в репозитории лежит только `.env.example`.

## 7. Docker

### 7.1 Состав

- **app** — Go-сервис.
- **db** — PostgreSQL с постоянным volume для данных.

### 7.2 Требования

- Dockerfile с multi-stage сборкой: сборка в образе с Go, запуск в минимальном образе.
- `docker-compose.yml` поднимает app и db одной командой `docker compose up`.
- Конфигурация через переменные окружения (`.env`): строка подключения к БД, JWT-секрет, ключи Stripe, порт.
- Healthcheck для PostgreSQL; app стартует после готовности БД.
- Миграции применяются автоматически при старте или отдельной командой.
- Файл `.dockerignore`.
- Для проверки webhook локально используется Stripe CLI (`stripe listen`), перенаправляющий события на эндпоинт webhook.

## 9. Этапы разработки

1. Каркас проекта, Docker Compose с PostgreSQL, миграции.
2. Регистрация, вход, JWT и middleware.
3. Товары: список, поиск, просмотр.
4. Админ-панель: CRUD товаров, остатки.
5. Корзина.
6. Заказы и checkout.
7. Интеграция со Stripe и webhook.
8. Dockerfile для приложения, полный запуск через Compose.
9. Проверка сценариев в Postman, README.
10. Простой фронтенд (по желанию).

## 10. Критерии готовности

- Весь пользовательский сценарий проходит в Postman: регистрация, вход, поиск, корзина, checkout, оплата тестовой картой.
- Обычный пользователь получает 403 на админских эндпоинтах.
- После успешной оплаты заказ `paid`, остатки уменьшены, корзина пуста.
- Проект запускается с нуля командой `docker compose up` по инструкции из README.
